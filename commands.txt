docking-ai — commands to push this project to GitHub yourself
================================================================
Run these from PowerShell, in C:\Users\faris-c\Documents\APK\Pytroch
Claude Code did NOT run any of these (git push / remote creation / GitHub
auth were explicitly out of scope) — they are for you to run manually.

0) Check what's here first (this project is not yet a git repo)
------------------------------------------------------------------
cd C:\Users\faris-c\Documents\APK\Pytroch
git status

1) Initialize the repo and make the first commit
------------------------------------------------------------------
git init
git add src tests configs pyproject.toml requirements.txt environment.yml README.md .gitignore data/raw/.gitkeep data/processed/.gitkeep
git status
git commit -m "Initial commit: docking-ai GNN + AutoDock Vina pipeline"

Do NOT run "git add -A" or "git add ." blindly — it would also stage
.venv/ and outputs/ if .gitignore isn't picked up for some reason. Double
check with "git status" before committing that only the files above (plus
command.txt if you want it tracked) are staged.

2) Create the GitHub repository
------------------------------------------------------------------
Option A — using GitHub CLI (if you have `gh` installed and authenticated):
gh auth login
gh repo create docking-ai --private --source=. --remote=origin

Option B — manually:
  - Go to https://github.com/new in your browser
  - Create a repository named "docking-ai" (public or private, your choice)
  - Do NOT initialize it with a README/.gitignore/license (this repo already
    has them; that would cause a conflicting history on first push)
  - Then run:
git remote add origin https://github.com/<your-username>/docking-ai.git

3) Push
------------------------------------------------------------------
git branch -M main
git push -u origin main

4) Ongoing workflow after this
------------------------------------------------------------------
git add <changed files>
git commit -m "<message>"
git push

Reminders
------------------------------------------------------------------
- .venv/ and outputs/ (checkpoints, logs, docking/screening/explain results)
  are gitignored on purpose — regenerable, and outputs/ may end up
  containing real docking results/data you don't want in a public repo.
- If you ever add a real labeled dataset under data/raw/ or data/processed/,
  check its license/redistribution terms before pushing it — .gitignore
  currently excludes everything under data/ except the .gitkeep files, so
  you'd need to deliberately un-ignore and add such files yourself.
